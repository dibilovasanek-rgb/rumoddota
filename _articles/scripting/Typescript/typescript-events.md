# События и таймеры в Typescript

Как вы, возможно, знаете, в Доте проводится множество мероприятий. При разработке собственной игры прослушивание событий очень полезно, поскольку позволяет вам что-то делать, когда что-то происходит. Например, прослушивание события, которое срабатывает при смерти, когда погибает герой, юнит или здание. События предоставят некоторую информацию об экземпляре этого события. Например, в приведенном выше событии в параметры будут включены убийца и жертва.

## Важное примечание, прежде чем мы начнем

В этом разделе есть множество асинхронных функций, которые имеют обратные вызовы в качестве аргументов. Если вы не знаете, что это такое, на W3Schools есть отличные и понятные статьи, объясняющие [callbacks](https://www.w3schools.com/js/js_callback.asp) и [async functions](https://www.w3schools.com/js/js_asynchronous.asp) по этому вопросу.

В этом руководстве будут рассмотрены и объяснены коды, написанные в шаблоне Typescript. Если у вас его нет, прочтите инструкции по [Typescript Introduction](typescript-introduction). Хотя в качестве примеров будет использоваться написанный код, не стесняйтесь поэкспериментировать с шаблоном и по-настоящему понять, как все это связано друг с другом.

## Встроенные события
Встроенные события, которых много, не могут быть изменены с точки зрения того, когда они запускаются и какие параметры предоставляются, так что имейте это в виду. Однако вы можете добавить прослушиватель к событию с помощью функции обратного вызова — функции, которая будет запускаться при срабатывании этого события.

Откройте файл `GameMode.ts` в папке `/src/vscripts` вашего проекта.
Там вы можете найти примеры событий, которые мы слушаем. Например, возьмем следующее событие:
```
ts
ListenToGameEvent('npc_spawned', (event) => this.OnNpcSpawned(event), undefined);
```
Вызов `ListenToGameEvent` создает нового прослушивателя этого события. В первом аргументе должно быть указано допустимое имя события. Typescript знает, какие имена событий разрешены, и отклонит любое другое имя, которое не является одним из известных событий. Мало того, он также знает, какие типы параметров передает каждое событие.
Вы можете использовать intellisense вашей IDE (например, в VSCode по умолчанию это Ctrl + пробел), чтобы отобразить имена всех событий, а затем просто выбрать нужное событие.

Затем вторым аргументом является функция обратного вызова. Обратите внимание, что он имеет синтаксис `event => SomeFunctionName(event)`, называемый синтаксисом выражения стрелочной функции. Это используется для определения функции, которая будет запускаться при срабатывании события. Учитывая объект `event`, описывающий событие, функция вызывается и выполняется так же, как и любой другой код.

Функция может быть внешней функцией, например `this.OnNpcSpawned` в приведенном выше примере, где она определена, или вы можете записать тело функции прямо здесь. Например:
```
ts
ListenToGameEvent(
  'npc_spawned',
  (event) => {
    print('we just fired npc spawned event!');
  },
  undefined,
);
```

:::info
I do not recommend writing function bodies in this manner unless it is a few lines at most, as the code can get messy and not very readable.
:::

As was already stated, Typescript knows what are the parameters provided when an event is triggered. They are stored in an object that we call `event`. If we're using an external function, that function should expect that event, which makes sure it is only used when the appropriate event runs.

In the example of `this.OnNpcSpawned(event)`, we defined an external function in the same class to call whenever the event triggers, which looks like this:

```
ts
OnNpcSpawned(event: NpcSpawnedEvent) {
    // After a hero unit spawns, apply modifier_panic for 8 seconds
    const unit = EntIndexToHScript(event.entindex) as CDOTA_BaseNPC; // Cast to npc since this is the 'npc_spawned' event
    // Give all real heroes (not illusions) the meepo_earthbind_ts_example spell
    if (unit.IsRealHero()) {
        if (!unit.HasAbility("meepo_earthbind_ts_example")) {
            // Add lua ability to the unit
            unit.AddAbility("meepo_earthbind_ts_example");
        }
    }
}
```
Здесь мы можем увидеть несколько вещей. Во-первых, `event: NpcSpawnedEvent`, который описывает тип события, требуемого для этой функции. Это имеет два преимущества: во-первых, если вы используете несовместимое событие и обратный вызов, Typescript немедленно уведомит вас об этом. Во-вторых, эта функция знает, какие параметры вам предоставлены для использования.

Если вы не уверены, какой тип вам следует использовать, вы можете навести указатель мыши на `event` в вызове прослушивателя событий, и Typescript сообщит вам, к какому типу относится это событие. Например, при наведении курсора на событие `npc_spawned` вы увидите тип `NpcSpawnedEvent`:

![Event type of predefined events](/images/typescript-tutorial/eventTypeOfPredefinedEvents.png)

Поскольку событие сработало, мы знаем, что что-то породило. В самой функции мы хотим знать, что породило, и обратиться к этому. Если мы проверим свойства события `NpcSpawnedEvent`, то увидим, что оно имеет два свойства: `entindex`, имеющее тип EntityIndex, и `is_respawn`, имеющее логический тип.

:::информация
Вы можете найти типы в редакторе, щелкнув тип и нажав F12.
:::

Энтиндекс относится к индексу сущности, который соответствует порожденной сущности. Если бы мы хотели получить саму сущность, нам нужно было бы привести ее к дескриптору, что можно сделать, вызвав `EntIndexToHScript`. Затем вы можете обратиться к этому объекту (обычно к юниту) и сделать все, что вам нужно, когда юнит появится. Вы также можете использовать свойство `is_respawn`, чтобы определить, возродился ли этот юнит, если он появлялся не в первый раз.

## Пользовательские события

В вероятном случае, когда встроенные события не охватывают ситуацию, в которой вы хотите вызвать событие, Dota позволяет вам создавать собственные события. Как и в случае со встроенными событиями, Typescript играет большую роль в создании пользовательских событий и обеспечении осмысленности типов этих событий.

Прежде чем мы начнем, мы должны сначала определить событие. Для этого мы используем файл .d.ts. Если хотите, вы можете узнать больше о файлах .d.ts [here](https://en.wikipedia.org/wiki/TypeScript#Declaration_files). Суть в том, что мы используем файлы .d.ts для описания Typescript типов вещей, доступных глобально.

Перейдите к `/src/common/events.d.ts`. Там вы можете использовать интерфейс `CustomGameEventDeclarations`, чтобы добавить столько пользовательских событий, сколько захотите. Шаблон разработал пользовательские события, которые будут извлекаться из событий, показанных в этом интерфейсе. Мы видим, что у него уже есть событие `example_event`, которое будет использоваться в качестве его имени, и тип `ExampleEventData`, который позже определяется как объект с различными свойствами, например `myNumber`.

:::информация
Папка `/common` составлена ​​для всех типов, составлена ​​как для серверной стороны, так и для панорам, таких как события или сетевые таблицы. Это означает, что вы можете определить событие один раз, и обе стороны могут увидеть и использовать это событие.
:::

Если вы хотите запустить пользовательское событие, вы можете использовать для этого функцию `CustomGameEventManager.Send_ServerToPlayer`. Существуют и другие варианты этой функции, но если проще, этот вариант отправляет событие конкретному игроку. В этом случае первый аргумент определяет, какому игроку отправить событие, а второй аргумент определяет, какое событие оно должно инициировать для этого игрока. Обратите внимание, что вы можете использовать только пользовательские события, которые были определены в интерфейсе `CustomGameEventDeclarations` — в противном случае Typescript выдаст ошибку. Третий аргумент формируется на основе выбранного события и обеспечивает отправку события со всей необходимой информацией для этого события.

Вы можете найти пример вызова функции `CustomGameEventManager.Send_ServerToPlayer` в `GameMode.ts`, который покажет, как все это связано друг с другом.

## Таймеры

Таймеры — это библиотека, написанная на lua. Мы можем использовать библиотеку таймеров для задержки действий на определенное время, после чего вызывается функция обратного вызова. Его можно использовать в качестве задержки или повторного вызова, который происходит, например, каждые несколько секунд.

:::информация
Таймеры написаны на lua. Вместо преобразования в Typescript мы используем файл `timers.d.ts`, чтобы описать Typescript структуру таймеров, что позволяет нам использовать библиотеку таймеров как есть.
:::

Возвращаясь к `GameMode.ts`, файл содержит пару примеров таймеров. В обоих случаях исполнение простое. Давайте рассмотрим один из них:```
ts
// Automatically skip setup in tools
if (IsInToolsMode()) {
  Timers.CreateTimer(3, () => {
    GameRules.FinishCustomGameSetup();
  });
}
```
Это фрагмент кода, который срабатывает, когда игра переходит на экран «Настройка пользовательской игры», где игроки могут распределять себя по командам. Чтобы разработчикам не приходилось ждать на этом экране при каждом запуске, мы добавили проверку — если это в режиме инструментов (то есть мы запускаем игру из инструментов Dota Workshop), то мы создаем таймер. Через 3 секунды мы запускаем `GameRules.FinishCustomGameSetup();`, который переходит к следующему шагу.

Обратите внимание, что код не ждет завершения таймера. Создается таймер, и код немедленно переходит к следующей строке. Когда в игре проходит указанное количество времени, таймер разрешается, выполняя предоставленную ему функцию обратного вызова.

Таймеры можно настроить на повтор, вернув числовое значение, обозначающее секунды. Например, мы могли бы создать следующий таймер:
```
ts
Timers.CreateTimer(5, () => {
  print(`The current time in dota is: ${GameRules.GetDOTATime()}`);
  return 1;
});
```
При этом будет создан таймер, выполнение которого первоначально занимает 5 секунд. Поскольку мы возвращаем 1, таймер будет повторяться каждую секунду. В этом примере при каждом выполнении будет выводиться текущее время и сообщение.

Обратите внимание, что вы можете возвращать разные значения при каждом запуске, чтобы таймер запускался с разными задержками при каждом повторении.
Кроме того, возврат без значения или с `undefined` приведет к тому, что таймер больше не будет повторяться, что можно использовать в качестве условия остановки для повторяющегося таймера.

:::информация
Таймеры уважают паузы. Это означает, что они не будут выполняться, пока игра приостановлена, и выполнение кода будет отложено до тех пор, пока игра не будет снята с паузы.
:::

## Использование таймеров с промисами для задержки кода
Иногда вам нужно создать последовательность эффектов, которые происходят один за другим, но не сразу, а по истечении короткого периода времени. Хотя вы могли бы сделать это в таймерах, это привело бы к созданию серии обратных вызовов, что может сделать код беспорядочным и трудным для чтения.

Вместо этого мы могли бы обернуть таймер в промис. Если вы не знаете о Promises, вы можете прочитать [Promises in W3Schools](https://www.w3schools.com/js/js_promise.asp). Мы также будем использовать промисы с концепцией async/await, которую вы можете прочитать на [Async/Awaits in W3Schools](https://www.w3schools.com/js/js_async.asp). Это довольно сложные темы, поэтому не стесняйтесь обсуждать их с нами в Moddota или искать дополнительные статьи или видео по ним.

Давайте создадим функцию `sleep`, которая будет возвращать обещание, которое разрешается при выполнении таймера. Обычно я создаю все служебные функции, подобные этой, в другом файле, обычно называемом `utils.ts`. Перейдите в папку `/src/vscripts/libs` и создайте файл с именем `utils.ts`.

Там мы хотим создать функцию сна, которая выглядит следующим образом:
```
ts
export function sleep(duration: number) {
  return new Promise((resolve, reject) => {
    Timers.CreateTimer(duration, () => resolve(''));
  });
}
```
Как видите, функция возвращает обещание, которое будет выполнено в какой-то момент в будущем. Вы можете подождать, пока обещание будет разрешено с помощью async/await. Для целей этого примера давайте рассмотрим функцию `OnNpcSpawned`. Он преобразует энтиндекс в юнит, а затем проверяет, настоящий ли это герой (например, не иллюзия). Затем, если у него нет способности, он немедленно дает ему эту способность. Давайте представим, что вместо этого мы хотим дать ему эту способность по прошествии 5 секунд.

Во-первых, поскольку мы хотим использовать `await`, мы должны преобразовать эту функцию в асинхронную функцию. Добавьте ключевое слово `async` прямо перед именем функции:
```
ts
private async OnNpcSpawned(event: NpcSpawnedEvent) {
```Затем импортируйте `sleep` из `utils.ts`:```
ts
import { sleep } from './lib/util';
```
И теперь мы можем спать на 5 секунд, используя await:
```
ts
private async OnNpcSpawned(event: NpcSpawnedEvent) {
    // After a hero unit spawns, apply modifier_panic for 8 seconds
    const unit = EntIndexToHScript(event.entindex) as CDOTA_BaseNPC; // Cast to npc since this is the 'npc_spawned' event
    // Give all real heroes (not illusions) the meepo_earthbind_ts_example spell
    if (unit.IsRealHero()) {
        if (!unit.HasAbility("meepo_earthbind_ts_example")) {
            // Wait for 5 seconds before giving it the ability
            await sleep(5);

            // Add lua ability to the unit
            unit.AddAbility("meepo_earthbind_ts_example");
        }
    }
}
```
Как видите, это делает код очень чистым и простым в использовании. Таким образом, неповторяющиеся таймеры можно перевести в спящий режим, чтобы добиться того же результата с более чистым потоком кода.

Есть много вещей, для которых вы можете использовать async/await, например, ожидание попадания следящих снарядов, ожидание завершения анимации и т. д.
