# Конвертация MDL в VMDL

В этом руководстве будет описан процесс создания файла **`.vmdl`** (модель Source 2) из файла **`.mdl`** и других файлов, связанных с моделью, из Source 1. В качестве примера будет использоваться курьер Wyvern Hatchling, но тот же процесс применим к героям, зданиям и любой модели Valve Dota.

<StaticVideo path="/videos/JauntyQuickArcticwolf.mp4" />

## Необходимые инструменты

- [GCFScape](https://developer.valvesoftware.com/wiki/GCFScape) или [Source 2 Viewer](https://s2v.app/)
- [Crowbar](https://steamcommunity.com/groups/CrowbarTool/discussions/0/617328415069203029/)
- [VTFEdit](https://developer.valvesoftware.com/wiki/VTFEdit)
- Инструменты мастерской (редактор материалов и моделей)

## Шаг 1. Получите файлы **model** и **material** из VPK основной игры (`pak01_dir.vpk`) с помощью GCFScape.

Требуются следующие типы файлов:

- `.mdl`
- `.vvd`
- `.dx90.vtx`
- `.vtf`

Файлы моделей будут находиться в подпапке папки _/models/_:
![img](/images/external/i3ayn-10871a9310.png)

Щелкните правой кнопкой мыши и извлеките файл в папку по вашему выбору.

![img](/images/external/i3aCO-4887dee9a8.png)

Файлы цветных материалов расположены в папке _materials/models/_. В этом примере у этого курьера есть 3 связанных файла цвета, по одному для каждого скина, поэтому мы получим

![img](/images/external/i3aCw-5df098fb34.png)

Наконец, у нас должно быть следующее:
![img](/images/external/i3aF1-ac40c1028e.png)

## Шаг 4. Переместите сгенерированные файлы в папку дополнений **/content/**.

- Переместите декомпилированные файлы, созданные на шаге 2, в **/content/models/**.

![img](/images/external/i3cT8-8962d8e943.png)

- Переместите файлы TGA, созданные на шаге 3, в **/content/materials/**.

![img](/images/external/i3cQg-76e8c16b46.png)

Создайте новые папки для каждого или просто перетащите файлы в соответствующие каталоги. Обязательно используйте папку содержимого (а не /game/). <br />Расположение эталонной сетки в /content/models/ определит место, где будет сохранен файл .vmdl.

## Шаг 5. Создайте файл `.vmat` из файлов TGA.

- Откройте редактор материалов.
- Файл -> Новый материал
- Пока ничего не делая, **сохраните** пустой материал с именем TGA, для которого вы хотите создать `.vmat`. ![img](/images/external/i3d02-b647383364.png)
- Просмотрите и найдите TGA для использования ![img](/images/external/i3d8I-b8d0e0b25d.png).
- По умолчанию файл должен быть виден с расширением `_color.` ![img](/images/external/Bbu4VtP.jpg).
- Сохраните окончательный материал. ![img](/images/external/Jbw6kyq.jpg)

## Шаг 6. Создайте новый VMDL из файла сетки (`.smd`)
- Откройте редактор моделей
- Новый VMDL из файла сетки (Ctrl+M) ![img](/images/external/i3gPC-eb6efe93f2.jpg)
- Выберите эталонный файл `.smd`, созданный на шаге 2. ![img](/images/external/Q7VH7Nq.png).
- Если все прошло хорошо, вы должны увидеть красную сетку ошибки: ![img](/images/external/MQmf1IM.jpg).

## Шаг 7. Добавьте переназначение материала для отсутствующих текстур, используя файл .vmat из шага 5.

- В меню Модель -> Добавить переназначение материала ![img](/images/external/NgZbK7n.png).
- Выберите список переназначения материалов и сверните свойства в редакторе свойств ![img](/images/external/oRNgV71.png).
- Поиск материала, выберите его из раскрывающегося списка. Это недостающие материалы, которые необходимо переназначить на созданный ранее .vmat.
- Ctrl+S, чтобы сохранить модель, теперь модель объединяется с текстурой и принимает форму:
![img](/images/external/o22c9Iy.jpg)

- ЕСЛИ на модели отображается сообщение **Ошибка**, что-то пошло не так. Обязательно удалите автоматически скомпилированные модели и одноименные материалы из папок /game/, которые теперь повреждены. Убедитесь, что все использует правильные имена и каталоги, иногда кажется, что редактор модели/материала не работает и делает что-то Volvo.

## Шаг 8. Добавьте анимации в папку `_anims` и создайте для них действия.

![img](/images/external/5BvFhPg.png)

Выберите их все.

![img](/images/external/GPPJld3.png)
Анимации теперь будут просматриваться при нажатии на них, модель будет двигаться, но для того, чтобы игра могла использовать анимацию, ей необходимо действие (строки ACT_DOTA_name).

В окне «Последовательности» («Инструменты выполнения» -> «Просмотр последовательностей», если оно не отображается) убедитесь, что выбран вариант **Активность**. Он покажет пустой список в скобках []

![img](/images/external/i3xPr-4ac46797fe.png)

Теперь выберите каждую анимацию, для которой вы хотите создать действие.

![img](/images/external/i3yr7-447456fe3a.png)

В редакторе свойств есть элемент «Действия», который по умолчанию будет содержать 0 элементов. Нажмите на ****+**, чтобы добавить его.
![img](/images/external/i3yyc-2bde52de31.png)

Добавьте к нему Имя, попробуйте использовать ACT_DOTA_name, которое лучше соответствует описанию действия.

![img](/images/external/i3yxi-2cbd4d5b16.png)

Наконец, у нас есть полезные анимации:

![img](/images/external/i3yyc-2bde52de31.png)

::: информация
Это также полезно для доступа к некоторым действиям ACT_DOTA_ACTIVITY+**string**, которые используются в некоторых анимациях насмешек и альтернативных анимаций, которые в настоящее время нельзя использовать для способностей и других целей (поскольку они просто игнорируют часть **+string**). Зная это, можно назначить некоторую неиспользуемую строку активности, например «ACT_DOTA_MINI_TAUNT», и принудительно использовать ее через `OverrideAnimation` KV.
:::
