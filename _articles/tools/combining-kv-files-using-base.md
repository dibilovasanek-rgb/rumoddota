# Объединение файлов KV с помощью #base

Наличие одного kv-файла, содержащего определения каждого юнита или способности, как это установлено по умолчанию в интерфейсе мода, может очень быстро стать очень раздражающим. Разделение этого файла на несколько файлов KV меньшего размера упрощает обзор и управление файлами. Обычно для этого используют модкиты, но:

**[ModKit](https://github.com/stephenfournier/Dota-2-ModKit) не требуется для объединения файлов KV**

Благодаря некоторой детективной работе, проделанной в #steamdb, и некоторому тестированию с моей стороны, мы обнаружили, что в dota KV есть рабочая директива #base, которая сообщает движку объединить другой файл KV с текущим.

**Этот метод работает для:**

- Файлы определения юнитов/способностей (например, `npc_units_custom.txt` или `npc_abilities_custom.txt`).
- Пользовательские файлы значений ключей, загружаемые в lua с помощью LoadKeyValues.
- Файлы локализации (`addon_english.txt`)

## Как это работает

Предположим, мы начинаем с одного файла по пути `scripts/npc/npc_abilities_custom.txt` со следующим содержимым:
```
"DOTAAbilities"
{
    "Ability1"
    {
        "SomeProperty1"    "1"
        "SomeProperty2"    "2"
    }

    "Ability2"
    {
        "SomeProperty1"    "1"
        "SomeProperty2"    "2"
    }
}
```
Теперь предположим, что мы хотим разделить это на два файла и создать еще один файл `scripts/npc/abilities_2.txt`. У этого файла должен быть корневой элемент, как и у других файлов, мы можем просто скопировать `DOTAAbilities`. Также скопируйте содержимое, которое нужно разделить, и вот результат:
```
"DOTAAbilities"
{
    "Ability2"
    {
        "SomeProperty1"    "1"
        "SomeProperty2"    "2"
    }
}
```
Теперь отредактируйте основной файл, включив в него новый файл `abilities_2.txt`, добавив `#base "[relativePath]"`. Результат:
```
#base "abilities_2.txt"
"DOTAAbilities"
{
    "Ability1"
    {
        "SomeProperty1"    "1"
        "SomeProperty2"    "2"
    }
}
```
При загрузке этого файла KV движок теперь автоматически добавит содержимое `abilities_2.txt` в `npc_abilities_custom.txt`, объединив два корневых объекта в обоих файлах. Это означает, что имя корневого объекта не имеет значения, поэтому вместо `"DOTAAbilities"` у вас может быть `"MYOTHERFILE"` или даже просто пустая строка `""`. У вас не должно быть одинаковых ключей в обоих корневых объектах, но если вы это сделаете, то те, которые определены позже (подумайте о том, что `#base` происходит до остальной части файла), переопределят уже определенные.

Это также поддерживает каталоги. Имейте в виду, что все пути относительны. Допустим, я создаю `scripts/npc/customAbilities/ability1.txt` и могу включить его из `scripts/npc/npc_abilities_custom.txt`, используя `#base "customAbilities/ability1.txt"`.

**PS:** Другие расширения также разрешены. Вы можете назвать включенные файлы `.kv`.
